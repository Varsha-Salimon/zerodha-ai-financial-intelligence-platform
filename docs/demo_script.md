# Demo Flow

This walkthrough is designed for a short technical/product demonstration of the deployed application.

## 1. Login

Start from the login screen and authenticate as a USER.

Explain that the application uses JWT authentication and separates investor access from administrative access.

## 2. User Dashboard

Show the portfolio-level view.

Point out total investment, current value, profit/loss, return percentage, and portfolio performance indicators. Explain that these metrics are calculated by deterministic application logic rather than generated by the language model.

## 3. Portfolio

Open the Portfolio page and show the holdings and portfolio metrics. Explain that portfolio data is scoped to the authenticated user.

If demonstrating upload, show the portfolio CSV upload flow and explain that the uploaded data feeds the same analytics workflow.

## 4. Analytics and Risk

Use the available portfolio/risk views to explain allocation, concentration, sector exposure, performance, stock contribution, volatility, drawdown, and benchmark context.

The key engineering point is that these calculations happen before the AI interpretation stage.

## 5. AI Insights

Open the AI Insights page.

Explain the workflow:

```text
Portfolio
  → deterministic analytics
  → MCP tools
  → Portfolio Agent
  → Google Gemini
  → structured output
  → validation
  → user-facing insight
```

Emphasize that the AI is not being asked to invent portfolio facts. It receives structured context assembled by the application and MCP layer.

## 6. Recommendations

Show the recommendation cards and explain the recommendation category/type, rationale, supporting metrics, confidence, data source, and informational disclaimer.

Explain that recommendations are intended as review/monitoring signals, not guaranteed outcomes or autonomous trading instructions.

## 7. User Settings

Show the user settings screen briefly to demonstrate the authenticated user experience and account-level separation.

## 8. Admin Login

Log out and sign in using an ADMIN account.

Explain that the administrative experience is separate from the investor experience and exposes operational/governance information rather than another investor's portfolio.

## 9. Admin Dashboard

Show the admin dashboard and highlight user count, AI execution activity, MCP execution activity, recommendation activity, backend/database health, MCP health, and governance status.

## 10. Operations

Open Operations and show AI/MCP execution monitoring. Explain that execution status, validation status, duration, tool names, and errors where available provide operational visibility into the AI workflow.

## 11. Compliance

Open Compliance and explain how the application surfaces governance and review information around AI-generated outputs.

The important design idea is that the AI workflow is observable and reviewable rather than a black-box chatbot.

## 12. Technical Close

Finish by summarizing the architecture:

> The platform combines a Next.js frontend, FastAPI backend, PostgreSQL database, deterministic analytics engine, MCP tool layer, Portfolio Agent, Google Gemini, validation controls, role-based security, and audit telemetry into one controlled financial-intelligence workflow.

Then mention the main scope boundary:

> The current prototype uses sample market and news data and does not execute trades. Live brokerage integration, real-time feeds, advanced risk models, and production-scale monitoring are future extensions.

## Demo Tips

- Keep the focus on the problem being solved rather than reading every UI label.
- Demonstrate one complete user journey before switching to ADMIN.
- Explain the AI workflow with the architecture diagram rather than relying on model output alone.
- Avoid presenting sample data as live market information.
- Avoid describing the system as autonomous trading or a multi-agent system.
